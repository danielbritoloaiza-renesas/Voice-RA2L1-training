# RA2L1 Voice Command Project

This project is a learning-oriented voice recognition demonstration based on the Renesas RA2L1 microcontroller family and the RA2L1 Voice board. It is designed to explore how a low-power embedded system can capture audio, detect trigger words, recognize commands, and respond in real time.

The implementation combines a Renesas RA2L1 board, a microphone input chain, DSpotter speech recognition, audio processing utilities, and a small set of companion modules for UART diagnostics, flash management, and optional audio playback.

This repository is useful both as:

- a technical learning project for understanding voice interfaces on embedded systems
- a client-facing example of a practical voice-command solution concept
- a starting point for product customization, wake-word tuning, and command-set expansion

---

## Project Purpose

The goal of this project is to demonstrate an embedded voice-command workflow on an ultra-low-power MCU platform. The system is intended to recognize a trigger phrase and then a command, enabling a compact device to respond to user voice input without relying on a cloud service.

Typical use cases include:

- smart home controls
- appliance interaction
- industrial operator assistance
- educational voice interface prototypes
- embedded AI and DSP experimentation

---

## Key Features

- Voice wake-word and command recognition using DSpotter
- Audio capture from microphone input
- AGC-based signal conditioning for recognition robustness
- Low-power operation mode for energy-sensitive applications
- UART trace and debug output for development and testing
- Optional Speex playback support for audio replay scenarios
- Data flash usage for storing recognition-related information
- Modular source organization for easier training and extension

---

## Hardware Platform

This project targets the Renesas RA2L1 Voice evaluation platform and related RA2L1 devices. The board includes the MCU, microphone support, and peripheral resources needed for embedded audio processing.

Typical hardware characteristics:

- Renesas RA2L1 MCU
- voice-capable board form factor
- microphone input path
- GPIO and debug interfaces
- UART connectivity for diagnostics and host communication

---

## Software Architecture

The application is organized around a voice-processing loop that initializes the audio pipeline, configures recognition resources, and continuously processes incoming audio data.

A high-level flow is:

1. Initialize UART, audio peripherals, and recognition engine
2. Load the model and command groups
3. Capture audio from the microphone
4. Perform recognition and trigger detection
5. Route recognized commands to the application logic
6. Provide debug output and manage low-power operation when needed

The codebase demonstrates integration points for:

- microphone recording
- buffering and data flow management
- model initialization
- recognition flow control
- optional low-power audio wake detection
- debug tracing and command reporting

## Main Components

### src/
Contains the core application logic and control flow.

- voice_main.c / voice_main.h: main recognition workflow and initialization
- hal_entry.c: board startup and entry point
- AudioRecord.c / AudioRecord.h: recording logic and buffering
- lpm_adc.c / lpm_adc.h: low-power sound detection utilities

### src/Model/
Contains the trained model assets and data used by the recognition engine.

- CybModel.asm
- CybModel.h
- SpeexData.asm
- SpeexData.h

### src/DSpotter/
Contains DSpotter-related adaptation and utility code.

### src/Speex/
Includes Speex audio support and playback-related modules.

### src/Util/
Contains helper modules for:

- UART communication
- flash handling
- trace logging
- buffer conversion
- platform-specific support

### ra/
Renesas FSP and board support code generated by the RA configuration toolchain.

### ra_cfg/
Configuration files for peripheral setup and generated middleware settings.

### ra_gen/
Generated driver and board initialization source files.

## Build and Development Notes

This project is built using the Renesas RA development environment and the Flexible Software Package (FSP). Development is typically done in the Renesas e2 studio workflow.

Important points:

- the board and MCU configuration are defined through generated RA files
- testing is typically done through UART logs and hardware validation
- model and recognition behavior may require tuning for command vocabulary and microphone conditions
- performance depends on audio quality, environmental noise, and selected trigger/command sets

---

## Typical Workflow

1. Open the project in the Renesas development environment
2. Review board configuration and peripheral setup
3. Build the firmware
4. Flash the binary to the RA2L1 board
5. Run the application and monitor UART output
6. Validate trigger and command recognition with live audio input
7. Adapt command vocabulary or power behavior based on the target product
